# AIPIWEN 上传报告输出规则 V0.1

## 1. 基本原则

上传报告后，系统不能直接生成泛化长文。必须先判断报告类型、对象、年龄阶段、用户目的、资料完整度和置信度，再选择对应模板。

同一份报告，根据用户目的调用不同模板；同一组指标，不同入口输出不同深度。

V0.2 增补：老师真实录音强调，上传报告后不能按报告死念，必须先看用户问题。新手可以先按标准流程走，但产品输出必须围绕用户目的组织。

## 2. 上传后必须先判断

| 判断项 | 说明 | 影响 |
| --- | --- | --- |
| 报告类型 | 个人、亲子、亲密关系、团队、未知报告 | 决定可用模板范围 |
| 报告对象 | 成人、孩子、家长、伴侣、合伙人、团队成员 | 决定表达语气和风险边界 |
| 年龄阶段 | 幼儿、小学、初高中、成人 | 决定学习、沟通、职业建议范围 |
| 用户目的 | 读懂报告、解释行为、生成完整报告、关系合看等 | 决定调用路径 |
| 人数结构 | 单人、双人、多人 | 决定是否可生成关系或团队报告 |
| 数据完整度 | 指标齐全、部分缺失、无法识别 | 决定置信度和是否追问 |
| 置信度 | 高、中、低 | 决定输出深度和断言强度 |

## 3. 上传后必须先问或识别的问题

核心问题：

> 你想用这份报告解决什么？

选项：

| 选项 | 用户目的 | 调用模板 |
| --- | --- | --- |
| A | 快速读懂这份报告 | 快速读懂版 |
| B | 理解孩子一个具体行为 | 孩子行为理解报告 + 案例库 |
| C | 生成个人完整理解报告 | 个人完整理解报告 |
| D | 生成亲子关系合看报告 | 亲子关系合看报告 |
| E | 生成亲密关系合看报告 | 亲密关系合看报告 |
| F | 生成团队协作理解报告 | 团队协作理解报告 |
| G | 做职业、学习、兴趣方向建议 | 个人完整报告中的建议模块 + 案例库 |

如果用户已经在提问中说明目的，可以直接识别；如果目的不清楚，先追问，不直接输出完整报告。

## 4. 输出深度规则

| 资料状态 | 可输出内容 | 不可输出内容 |
| --- | --- | --- |
| 指标齐全且目的明确 | 完整模板报告 | 医学、心理诊断或绝对结论 |
| 指标部分缺失 | 已知指标的解释 + 缺失提示 | 伪造缺失指标 |
| 只上传图片或截图 | 初步识别 + 追问 | 直接生成完整报告 |
| 仅用户口述 | 行为理解或低置信度建议 | 当作正式测评结论 |
| 关系资料只有一方 | 单方视角理解 | 生成双方确定性关系结论 |

## 5. 上传报告调用流程

1. 上传文件。
2. 识别报告类型。
3. 提取可识别指标。
4. 判断报告对象、年龄阶段和人数结构。
5. 识别或追问用户目的。
6. 判断数据完整度和置信度。
7. 选择报告模板。
8. 调用指标解释卡、场景规则、案例卡和版式模板。
9. 输出报告，并附边界说明。

## 6. 行为理解调用流程

1. 用户描述行为。
2. 识别行为场景：学习、情绪、沟通、亲子、关系、团队协作。
3. 调用案例库中相近场景。
4. 调用可能相关指标，不把指标当作唯一原因。
5. 输出“这个行为不一定代表什么”“可能涉及什么”“可以怎么回应”。
6. 如果长期影响睡眠、学习、情绪或生活，提示寻求专业评估。

## 7. 皮纹速测调用流程

1. 用户选择或描述纹型。
2. 生成低置信度基础画像。
3. 调用简版指标卡。
4. 输出轻量理解和下一步采集建议。
5. 明确提示：速测不能替代完整采集和人工校验。
6. 不输出确定性结论，不做诊断。

## 8. 关系合看调用流程

1. 收集双方或多方资料。
2. 比较 TRC、ATD、性格类型、学习通道、行为模式和五大功能区。
3. 识别差异，不做优劣判断。
4. 转换为冲突点、互补点和沟通翻译。
5. 输出场景建议和行动计划。
6. 不劝分、不劝合、不判断谁有问题。

## 9. 输出前安全检查

输出前必须检查：

- 是否出现医学或心理诊断表达。
- 是否出现绝对化表达。
- 是否出现伤害性标签。
- 是否使用“合盘”作为前台主词。
- 是否把老师现场口语或外部培训原话直接输出。
- 是否把低置信度资料写成确定结论。

不通过安全检查时，必须改写或停止输出。

## 10. V0.2 真实录音增补：问题导向路由

同一份报告进入系统后，先问“你想用这份报告解决什么”，再路由：

| 用户问题 | 解读重点 | 调用模块 |
| --- | --- | --- |
| 我想快速看懂报告 | 先解释核心指标和最明显特质 | 快速读懂版 + 指标卡 |
| 我适合做什么职业 | 当前工作优势、专业背景、过往资源、未来验证方向 | 个人完整报告 + 职业建议模块 + 案例库 |
| 孩子为什么这样 | 行为场景、常见误判、底层节奏、回应方式 | 孩子行为理解报告 + 亲子案例卡 |
| 我和孩子怎么沟通 | 家长底色、孩子底色、误解点、陪伴建议 | 亲子关系合看报告 |
| 亲密关系为什么冲突 | 双方差异、冲突触发、沟通翻译、行动计划 | 亲密关系合看报告 |
| 团队怎么协作 | 角色分布、协作冲突、会议与反馈机制 | 团队协作理解报告 |

硬规则：

- 不因报告完整就默认生成长文。
- 不因用户上传双人资料就默认生成关系结论。
- 不因某项指标高低就直接给职业、婚姻或孩子发展定论。
- 如果用户目的和资料类型不匹配，先说明可做范围，再追问或降级输出。

## 11. V0.2 真实录音增补：职业建议输出规则

成人职业建议采用“四步法”：

1. 先确认用户的问题：当前行业困惑、职业转型、优势发挥还是长期规划。
2. 先找现有工作里的优势调用点，不否定当前收入和资源。
3. 再看专业背景、过往经历、失败线索和可迁移资源。
4. 最后给过渡比例，例如 80% 稳定主业 + 20% 验证新方向。

可输出：

- “先在现有工作里增加更匹配你的角色比例。”
- “用小比例时间验证新方向，避免一次性推翻当前生活结构。”
- “过去没有做成的经历可作为风险线索，用来设计更稳的路径。”

禁止输出：

- “你现在行业选错了。”
- “你一定适合 / 一定不适合某职业。”
- “马上换方向。”

## 12. V0.2 真实录音增补：AI 解读分层

| 层级 | 触发方式 | 输出范围 | 边界提示 |
| --- | --- | --- | --- |
| 免费基础解释 | 用户只想看懂基础指标 | 指标、区间、基础含义 | 只解决基础理解，不做复杂判断 |
| AI 问答式解读 | 用户上传报告后围绕问题追问 | 教养、职业、兴趣班、陪伴方式、关系沟通 | AI 是辅助，不等于专家判断 |
| 人工专家深度解读 | 复杂亲子、亲密关系、职业转型、团队冲突或长期困扰 | 深度组合判断和行动方案 | 不自动前台输出 |

当用户问题牵涉心理风险、长期困扰、重大财务选择或严重关系冲突时，必须提示人工专家或专业支持，不由 AI 自动给结论。

## 13. V0.3 关系报告上传处理规则

### 13.1 上传双人报告

处理流程：

1. 识别关系类型：亲密、亲子、合伙人或其他双人关系。
2. 分别提取双方指标：TRC、ATD/APD、性格类型、学习/沟通通道、行为模式、左右脑、五大功能区。
3. 建立双方对照表。
4. 判断资料完整度和置信度。
5. 追问用户最想解决的关系场景。
6. 选择亲密、亲子或合伙人报告版式。
7. 输出差异、冲突、互补、沟通翻译和行动计划。

禁止：直接输出“你们合不合适”“谁的问题更大”“关系一定会怎样”。

### 13.2 上传多人报告

处理流程：

1. 识别人数、团队类型和成员角色。
2. 对齐所有成员的核心指标。
3. 统计团队节奏、情绪/决策节奏、沟通通道、行为模式和五大功能区分布。
4. 输出团队整体画像、角色定位、冲突矩阵和会议机制。
5. 当资料不完整时，只输出团队协作观察建议。

禁止：成员优劣排序、招聘淘汰建议、风险人员筛查。

### 13.3 单人报告生成关系参考

只有单人报告时，只能输出“单方关系模式参考”：

- 这个人在关系中可能如何表达需求。
- 容易被别人误解的地方。
- 适合他的沟通方式。
- 与他人协作时需要补充询问的资料。

禁止输出另一方画像、双方关系结论或关系成败判断。

### 13.4 多份报告指标对齐

对齐顺序：

| 顺序 | 指标 | 对齐目的 |
| --- | --- | --- |
| 1 | TRC | 看信息节奏和任务节奏差异 |
| 2 | ATD / APD | 看情绪、反应和恢复节奏 |
| 3 | 性格类型 | 看表达路径和误解点 |
| 4 | 学习 / 沟通通道 | 看信息接收与沟通方式 |
| 5 | 行为模式 | 看启动、构思和执行方式 |
| 6 | 左右脑底色 | 看整体感受与逻辑拆解差异 |
| 7 | 五大功能区 | 看目标、表达、行动、倾听、判断的互补与冲突 |

如果任何关键指标缺失，必须在报告中标注缺失，并降低置信度。

### 13.5 关系报告生成前追问

至少追问：

1. 你们是什么关系：亲密、亲子、合伙人、团队或其他。
2. 你现在最想解决的具体场景是什么。
3. 双方 / 多方是否都有完整报告。
4. 你希望报告偏“快速理解”“完整关系报告”还是“行动计划”。
5. 是否存在长期情绪、睡眠、暴力、自伤、重大财务或法律风险。

### 13.6 关系报告置信度

| 置信度 | 条件 | 可输出 |
| --- | --- | --- |
| 高 | 双方 / 多方核心指标完整，关系类型和问题明确 | 完整关系合看报告 |
| 中 | 指标基本完整，但缺少部分场景信息 | 关系结构分析 + 追问建议 |
| 低 | 只有一方报告、资料缺失或只描述行为 | 单方关系模式参考 / 行为理解建议 |
| 不可生成 | 无法确认关系类型、资料来源或用户目的 | 只输出需要补充的信息清单 |

### 13.7 关系报告降级规则

- 只有一方报告：输出单方关系模式参考。
- 双方报告完整：可输出关系合看报告。
- 多人资料不足：输出团队协作观察建议。
- 指标不完整：输出低置信度建议。
- 用户只描述行为：转入行为理解板块。

## 14. V0.4 AI 个性化报告与多视角输出规则

V0.4 将行业大会资料中的 AI 个性化报告方向转化为上传报告板块的产品规则。核心原则是：AI 帮用户更快理解报告和场景，不替代专家判断，不把潜能辅助参考写成诊断或命运结论。

### 14.1 多视角解读

同一份报告可以按不同用户身份切换输出视角：

| 视角 | 输出重点 | 禁止输出 |
| --- | --- | --- |
| 家长视角 | 孩子的学习方式、沟通方式、陪伴建议、环境支持 | 给孩子贴标签、判断家庭失败 |
| 孩子视角 | 用更容易接受的语言解释优势、压力点和行动建议 | 让孩子承担成人化判断 |
| 老师视角 | 课堂互动、反馈方式、任务结构和家校沟通建议 | 评价老师处理对错或筛查问题学生 |
| 解读师视角 | 指标组合、置信度、追问路径和人工判断提示 | 把内部术语原样输出给用户 |
| 成人本人视角 | 自我理解、职业学习建议、关系沟通和行动验证 | 直接给职业定论或人生判断 |

### 14.2 年龄段适配

上传报告必须识别年龄段或先追问年龄段，再选择表达重点：

| 年龄段 | 报告重点 | 输出边界 |
| --- | --- | --- |
| 0-6 岁 | 早期观察、亲子陪伴、环境支持 | 不做能力定型 |
| 7-12 岁 | 学习方式、兴趣启蒙、任务结构 | 不做升学或成绩承诺 |
| 13-18 岁 | 学习压力、情绪沟通、自我认同 | 不做心理诊断 |
| 19-25 岁 | 专业选择、职业探索、能力验证 | 不替代志愿或职业决策 |
| 26 岁以上 | 自我理解、关系、职业转型 | 不鼓励一次性推翻现有生活结构 |

### 14.3 场景适配

用户上传同一份报告后，必须先确认场景，再选择模板：

| 场景 | 可生成内容 | 需要调用 |
| --- | --- | --- |
| 快速读懂 | 核心指标、优势倾向、注意事项 | 指标卡 + 简版模板 |
| 个人完整 | 性格、学习、行为、职业学习建议 | 指标本体 + 完整模板 |
| 孩子行为 | 行为场景解释和回应建议 | 案例库 + 儿童安全边界 |
| 亲子关系 | 双方差异、误解点、沟通翻译 | 关系合看模板 + 话术库 |
| 亲密关系 | 情绪节奏、需求表达、冲突修复 | 关系合看模板 + 风险检查 |
| 合伙人 / 团队 | 角色分布、协作机制、会议建议 | 团队模板 + 多人对齐规则 |
| 班级画像 | 班级学习通道、任务节奏、家校沟通 | 群体统计 + 脱敏规则 |
| 企业团队画像 | 协作风格、岗位沟通、组织建议 | 团队画像 + 隐私授权 |

### 14.4 AI 个性化报告生成流程

1. 识别报告来源、完整度和关键指标。
2. 识别用户身份：家长、孩子、老师、解读师、本人、企业或机构。
3. 追问用户目的和使用场景。
4. 识别年龄段、关系类型或组织场景。
5. 选择输出模板：快速读懂、个人完整、孩子行为、亲子、亲密、团队、职业学习建议等。
6. 调用指标卡、案例卡、关系卡、安全规则和版式模板。
7. 标注置信度、资料缺口和需要补充的问题。
8. 对复杂心理、医学、法律、财务、重大关系风险转人工专家。

### 14.5 AI 与专家协作边界

- AI 负责整理、改写、路由、多视角生成和常见问题解释。
- 专家负责复杂组合判断、长期个案、关系冲突、职业重大决策和风险识别。
- AI 输出必须保留“辅助理解、需要结合真实场景验证”的边界。
- AI 不输出诊断、命运预测、绝对化职业建议、未成年人定型判断。

### 15.2 上传报告总流程

上传报告必须按以下顺序处理：

1. 接收上传。
2. 识别资料类型。
3. 识别主体与关系。
4. 识别用户身份。
5. 识别用户目的。
6. 检测完整度。
7. 检测风险。
8. 计算置信度。
9. 选择报告模板。
10. 必要追问。
11. 生成报告。
12. 安全改写。
13. 输出行动建议。
14. 判断是否建议人工专家。
15. 记录可沉淀知识卡。

任何步骤失败，都不能强行进入完整报告；必须追问、补资料、安全降级、转人工或建议专业帮助。

### 15.3 报告模板选择逻辑

模板选择优先级：

1. 风险等级优先：R3 不进入普通模板。
2. 授权优先：未成年人、多人、班级、团队资料未授权时只能安全降级。
3. 主体数量优先：单人、双人、多人分别进入个人、关系、团队/班级候选模板。
4. 用户目的优先：快速读懂、行为问题、关系冲突、职业学习、专家深度解读分别走不同模板。
5. 置信度收口：high / medium 可输出结构化建议，low / insufficient 只能降级或追问。

### 15.4 风险等级引用

| 风险等级 | 上传报告动作 |
| --- | --- |
| R0 | 正常按模板输出 |
| R1 | 安全改写后输出 |
| R2 | 进入安全降级版，必要时建议人工复核 |
| R3 | 禁止 AI 直接输出结论，必须拒绝风险结论、转人工或建议专业帮助 |

### 15.5 置信度引用

| 置信度 | 输出策略 |
| --- | --- |
| high | 输出结构化建议和行动计划 |
| medium | 输出倾向性解释，并提示补充信息 |
| low | 只输出观察方向和温和追问 |
| insufficient | 不做判断，只说明缺少信息并追问或转人工 |

### 15.6 转人工触发引用

以下情况必须建议人工专家或专业支持：

- 用户明确要求深度解读。
- 报告不完整但用户要求结论。
- 亲密关系或亲子关系出现长期严重冲突。
- 未成年人出现明显心理困扰。
- 涉及自伤、自杀、暴力倾向。
- 涉及医学或心理诊断。
- 涉及职业重大转型。
- 涉及团队人员淘汰或学校个体风险标签。
- 涉及高付费客户深度服务。

AI 可以先做资料整理、缺口说明和安全边界提示，但不能替代专家输出复杂结论。

## 16. V0.6 Prompt Pack 引用规则

V0.6 已建立 `10_prompt_pack_提示词包/`。上传报告板块后续应按“Schema 控制流程，Prompt 负责生成表达”的方式调用，不允许跳过 Schema 直接调用报告生成 Prompt。

### 16.1 Schema 到 Prompt 的调用流程

1. 上传资料进入 `AIPIWEN_上传报告解析Prompt_V0.1.md`，输出结构化字段。
2. 若用户目的、年龄、关系、授权或关键指标缺失，调用 `AIPIWEN_追问生成Prompt_V0.1.md`。
3. 根据风险等级判断是否调用普通报告 Prompt、`AIPIWEN_降级输出Prompt_V0.1.md` 或 `AIPIWEN_转人工建议Prompt_V0.1.md`。
4. 根据 `selected_report_type` 调用对应报告生成 Prompt。
5. 报告草稿必须经过 `AIPIWEN_安全改写Prompt_V0.1.md`。
6. 最后再次检查是否命中转人工触发。

### 16.2 报告类型与 Prompt 对应表

| report_type | Prompt 文件 | 备注 |
| --- | --- | --- |
| quick_read_report | `AIPIWEN_快速读懂报告Prompt_V0.1.md` | 控制字数，输出 3 个重点和下一步 |
| individual_full_report | `AIPIWEN_个人完整解读Prompt_V0.1.md` | 单人完整理解，必须保留边界 |
| child_behavior_report | `AIPIWEN_孩子行为理解Prompt_V0.1.md` | 行为不等于标签，家长行动建议 |
| parent_child_report | `AIPIWEN_亲子关系合看Prompt_V0.1.md` | 亲子差异、冲突循环、沟通翻译 |
| intimate_relationship_report | `AIPIWEN_亲密关系合看Prompt_V0.1.md` | 不劝分、不劝合、不判断谁对错 |
| partner_collaboration_report | `AIPIWEN_合伙人关系合看Prompt_V0.1.md` | 协作机制，不做法律/财务判断 |
| team_collaboration_report | `AIPIWEN_团队协作理解Prompt_V0.1.md` | 不用于招聘淘汰、成员排序、风险筛查 |
| career_learning_report | `AIPIWEN_职业与学习建议Prompt_V0.1.md` | 职业和学习探索，不做命定结论 |
| safety_limited_report | `AIPIWEN_降级输出Prompt_V0.1.md` | 资料不足、风险较高或低置信度时使用 |

### 16.3 通用 Prompt 调用边界

- 所有 Prompt 都必须继承 `AIPIWEN_系统总提示词_V0.1.md` 的角色和禁用规则。
- 所有报告生成 Prompt 都必须接受 `risk_flags` 和 `confidence_level`。
- R3 风险不调用普通报告 Prompt。
- low / insufficient 置信度不生成完整报告。
- 输出前必须调用安全改写 Prompt 或执行等价安全检查。
- 复杂、高风险或高付费深度服务必须建议人工专家复核。

- 模板选择失败：回到报告类型与模板选择 Schema 修正。

- 低置信度输出过度：回到置信度与降级输出 Schema 修正。

## 18. V0.8 外部培训吸收后的补充规则

V0.8 将外部机构培训资料中的行为倒推、后天环境校正、ATD/APD 深解和交付流程补充进上传报告规则。该补充不改变安全边界，不允许把外部机构原话直接作为前台输出。

### 18.1 行为输入优先规则

当用户只描述行为，未上传完整报告，或报告与行为场景不匹配时，系统必须按以下顺序处理：

1. 复述用户看到的行为和场景。
2. 明确“单一行为不能直接判断类型、人格或问题”。
3. 追问场景：发生时间、任务类型、持续多久、谁在场、用户希望解决什么。
4. 给出 2-3 个可能来源：任务结构、输入通道、身体参与、压力反应、关系互动、后天训练。
5. 只给低风险观察动作，不生成完整画像。
6. 必要时建议上传报告或转人工专家。

### 18.2 后天环境校正规则

上传报告输出必须纳入以下校正公式：

`先天倾向 + 后天环境 + 当前场景 = 当下表现`

执行要求：

- 先天倾向只来自报告中可识别的指标。
- 后天环境包括家庭、学校、职业、训练、关系、文化和长期经历。
- 当前场景包括任务压力、关系对象、时间限制、身体状态和用户目的。
- 当下表现只能作为观察结果，不能反推为固定人格。

### 18.3 用户说“报告不准 / 不像我”的流程

1. 先接住用户反馈，不争辩报告一定准确。
2. 检查报告来源、采集质量、资料完整度和指标可读性。
3. 询问是哪一部分不像：性格、学习方式、关系、职业、某个指标或行为解释。
4. 追问后天变量：是否被家庭、学校、职业、长期训练或当前角色强化/压抑过。
5. 区分三类情况：资料缺失、表达过度、当前状态与底层倾向不一致。
6. 降低置信度，输出“可能方向 + 追问 + 观察动作”。
7. 如涉及重大关系、职业、心理、医学或未成年人高风险，建议人工专家复核。

### 18.4 ATD/APD 深解规则

ATD/APD 只可作为理解反应节奏、感受方式和压力恢复的参考：

- 可讲：反应速度、关注角度、情绪温度、恢复方式、环境适配。
- 不可讲：好坏高低、心理疾病、医学判断、命运结论、职业或关系确定结论。
- 复杂输出必须结合年龄、场景、后天环境和用户反馈。

### 18.5 外部培训资料使用限制

- 外部机构课程、认证、代理和咨询交付话术只作为服务流程参考。
- 现场口语、夸张表达、医学化表达、命理化表达和标签化表达不得直接复用。
- 所有由 V0.8 引入的规则必须经过 V0.5 Schema、V0.6 Prompt Pack 和 V0.7 测试样本验证后，才能进入后续产品改造。
