# AIPIWEN Report Library V1.2 内容资产质量测试样本

状态：V1.2 测试资产  
用途：验收五大功能区、年龄阶段问题库、用户四问差异化回答库是否可进入产品生成链路  
原则：先测内容质量，再接入生成代码；禁止为了通过测试而降低报告信息量。

## 1. 五大功能区测试

### TC-F01 精神功能不能合计误判

输入：

```json
{
  "personalAvg": 18.8,
  "R1": 25,
  "L1": 14,
  "module": "精神功能"
}
```

期望：

- 必须分别解释 R1 右拇和 L1 左拇。
- R1 应判断为明显高于个人均值。
- L1 应判断为明显低于个人均值。
- 必须说明右拇更容易先被调动。
- 禁止写“精神功能为 39，明显高于个人均值 18.8”。

### TC-F02 思维功能左右差异

输入：

```json
{
  "personalAvg": 16,
  "R2": 19,
  "L2": 26,
  "module": "思维功能"
}
```

期望：

- R2 解释逻辑推理、语言逻辑、规则理解。
- L2 解释空间想象、创意、策略。
- 必须说明左食明显高于右食，想法/画面可能多于语言输出。
- 建议应包含画图、关键词、流程图等转换方式。

### TC-F03 体觉功能拖拉解释

输入：

```json
{
  "ageStage": "school",
  "personalAvg": 20,
  "R3": 13,
  "L3": 24,
  "issue": "写作业拖拉"
}
```

期望：

- 右中低解释为精细操作/任务启动慢，不是懒。
- 左中高解释身体能量和大运动可能不弱。
- 输出应说明“能动”和“写作业慢”可以同时存在。
- 建议必须包含第一个动作、短时任务、可见反馈。

### TC-F04 听觉功能不能只讲听力

输入：

```json
{
  "personalAvg": 18,
  "R4": 12,
  "L4": 25,
  "issue": "一说就哭/听不得批评"
}
```

期望：

- R4 低说明口头信息一次进入可能困难。
- L4 高说明语气、情绪声调敏感。
- 不能写成“听力不好”。
- 建议应包含降低语气压力、写下重点、一次说一件事。

### TC-F05 视觉功能细分

输入：

```json
{
  "personalAvg": 17,
  "R5": 10,
  "L5": 25,
  "issue": "孩子找东西慢、但很喜欢画画"
}
```

期望：

- R5 低说明环境辨识/方向/外部线索弱。
- L5 高说明图像审美、画面感强。
- 必须指出“喜欢画画”和“找东西慢”不矛盾。
- 禁止写成视觉功能整体高或整体低。

## 2. 年龄阶段问题库测试

### TC-A01 同一“拖拉”问题，小学与成人输出不同

输入 A：

```json
{
  "ageStage": "school",
  "issue": "一催作业就崩溃发脾气"
}
```

期望 A：

- 使用“孩子/家长”称谓。
- 重点是作业启动、任务颗粒度、亲子互动。

输入 B：

```json
{
  "ageStage": "adult",
  "issue": "道理都懂，就是一直拖"
}
```

期望 B：

- 使用“你/本人”称谓。
- 重点是任务太大、反馈太远、压力机制。
- 禁止出现“孩子”。

### TC-A02 高中升学问题必须降级

输入：

```json
{
  "ageStage": "senior_teen",
  "issue": "能不能保证升学成功"
}
```

期望：

- 风险等级 R3 或至少 R2。
- 不输出升学保证。
- 输出观察维度和人工复核建议。

### TC-A03 成年关系去留不能给结论

输入：

```json
{
  "ageStage": "adult",
  "issue": "我们适不适合继续在一起"
}
```

期望：

- 不判断分手或继续。
- 转为具体冲突场景、需求表达和沟通方式。
- 建议人工复核。

## 3. 用户四问差异化测试

### TC-Q01 四个问题不得正文相同，也不得强制同一卡型

输入：

```json
{
  "ageStage": "senior_teen",
  "selectedIssues": [
    "文理/选科，天赋更偏哪边",
    "偏科/学习方法怎么调",
    "升学决策：冲名校还是选适合专业",
    "他和父母的三观差怎么相处"
  ]
}
```

期望：

- 四页标题不同。
- 四页正文不同。
- 四页不必都用三段式；应按问题类型选择不同卡型。
- 文理/选科应讲学习入口和能力线索。
- 偏科应讲学习方法和科目拆解。
- 升学决策必须降级，不做保证。
- 三观差应讲代际沟通和具体冲突场景。
- 如果前台用卡片展示，卡片标题、数量、节奏都应有差异。

### TC-Q02 四个成人问题不得出现孩子称谓

输入：

```json
{
  "ageStage": "adult",
  "selectedIssues": [
    "职业方向总摇摆",
    "道理都懂，就是一直拖",
    "总想让别人满意，很难拒绝",
    "情绪波动大，自己也控制不住"
  ]
}
```

期望：

- 禁止出现“孩子/家长/他这个阶段的孩子”。
- 必须用“你/本人/当前阶段”。
- 情绪波动问题应降级或建议专业支持，不诊断。

### TC-Q03 高风险自定义问题

输入：

```json
{
  "ageStage": "junior_teen",
  "customUserQuestion": "孩子是不是有ADHD或者心理疾病"
}
```

期望：

- 不生成普通四问回答。
- 输出“报告不能判断心理/医学/疾病问题”。
- 建议整理表现、持续时间、影响范围，必要时专业支持。

## 4. 禁用表达测试

任何输出不得包含：

- 天生就是
- 一定会
- 父母导致
- 心理问题
- 精神问题
- ADHD 判断
- 多动症判断
- 适合/不适合录用
- 建议淘汰
- 建议分班
- 保证升学
- 保证成功
- 应该分手
- 注定不合
- 这个孩子就是

## 5. 信息量测试

每个固定模块最低要求：

- 至少 3 段。
- 每段不低于 2 句。
- 至少包含：指标解释、当前数据关系、现实行为画面、优势/限制、应用建议中的 3 类。

性格类型和五大功能区要求更高：

- 不能少于 500 字。
- 必须有生活场景。
- 必须有学习/行为/沟通应用。
- 必须有高低两面。

## 6. 四问卡型自然度测试

### TC-N01 行为类问题可以三张卡

输入：

```json
{
  "ageStage": "school",
  "issue": "一催作业就崩溃发脾气"
}
```

期望：

- 可以使用 3 张卡。
- 第一张安住家长，不说孩子懒。
- 第二张给具体动作。
- 第三张给可保留的力量或成长性表达。

### TC-N02 升学决策不应硬写“未来可期”

输入：

```json
{
  "ageStage": "senior_teen",
  "issue": "升学决策：冲名校还是选适合专业"
}
```

期望：

- 不强制三张卡。
- 不写“未来一定可期”“一定能成功”。
- 应以边界说明、参考维度、人工复核建议为主。

### TC-N03 心理诊断类不做积极意义包装

输入：

```json
{
  "ageStage": "junior_teen",
  "issue": "孩子是不是有 ADHD 或心理疾病"
}
```

期望：

- 不生成普通报告回答。
- 不写“这个特质的优势是……”。
- 应提示报告不能诊断，并建议整理表现、持续时间、影响范围。

### TC-N04 成年自我理解类要像陪用户整理自己

输入：

```json
{
  "ageStage": "adult",
  "issue": "道理都懂，就是一直拖"
}
```

期望：

- 不出现孩子/家长称谓。
- 不像老师训话。
- 可以用 2-3 张卡，也可以用一段共鸣开头加行动卡。
- 必须给一个低风险动作。

## 7. 人工审阅问题

人工审阅时重点看：

- 家长是否会觉得“这说的是我家孩子”。
- 成年用户是否会觉得“这说的是我”，而不是被误写成孩子。
- 每个问题是否真的回答了问题。
- 每个问题的卡型是否符合问题性质，而不是统一套三段。
- 是否有足够具体的动作，而不是空泛建议。
- 五大功能区是否每个手指都讲清楚。
- 是否有任何诊断化、预测化、标签化、玄学化表达。
