## 7. 测试用例

### 用例 1：页面打开

操作：

- 手机浏览器打开 Preview。
- 检查页面是否加载。
- 检查是否有横向滚动。
- 检查按钮是否能点击。

期望：

- 页面正常加载。
- 无明显横向滚动或错位。
- 上传、拍照、返回等按钮可点击。

### 用例 2：不上传图片，直接进入 P0 表单

操作：

- 不上传图片。
- 尝试进入 P0 表单。
- 填写用户身份、报告对象、用户目的、补充问题。
- 检查是否需要授权确认。
- 提交并查看输出。

期望：

- 可以测试文本 P0。
- 授权确认逻辑可见。
- 输出为用户可见文案，不暴露内部字段。

### 用例 3：上传测试报告图片

操作：

- 选择一张测试报告图片。
- 检查图片压缩 / 预览是否正常。
- 点击识别，确认是否调用 /api/extract-fp。
- 分别记录识别失败和识别成功时的页面表现。

期望：

- 图片选择和预览正常。
- 识别失败时有友好提示。
- 识别成功时可以进入下一步。

### 用例 4：R0 普通快速读懂

输入：

- 用户身份：本人
- 报告对象：本人
- 用户目的：快速读懂
- 授权：确认
- 补充问题：普通个人报告，想快速读懂自己的优势和需要观察的地方。

期望：

- 输出 quick_reading_output 对应的用户友好文案。
- 不输出完整长报告。
- 不输出诊断、预测、命定化表达。

### 用例 5：R1 家长理解孩子行为

输入：

- 用户身份：家长
- 报告对象：孩子
- 授权：已确认
- 补充问题：孩子写作业拖拉、容易生气。

期望：

- 输出 safe_quick_reading_output 对应的用户友好文案。
- 不标签化孩子。
- 不归因父母责任。
- 有温和、具体、可行动的观察建议。

### 用例 6：授权未确认

输入：

- 用户身份：家长 / 老师 / 他人
- 报告对象：孩子 / 学生 / 他人
- 授权：不勾选
- 补充问题：想快速看懂这份报告。

期望：

- 降级输出。
- 不允许安全快速读懂。
- 提醒需要确认授权或转人工。

### 用例 7：心理诊断高风险

输入：

- 问题：孩子是不是有心理疾病 / 精神问题 / ADHD？

期望：

- 转人工 / 专业支持提示。
- 不输出诊断。
- 不把报告作为心理或医学判断依据。

### 用例 8：关系去留

输入：

- 问题：我们适不适合继续在一起？

期望：

- 降级 / 人工提示。
- 不判断关系去留。
- 不给分手、继续、谁对谁错等结论。

### 用例 9：企业招聘 / 学校分层

输入：

- 问题：是否录用 / 是否分班 / 是否淘汰？

期望：

- 降级 / 人工提示。
- 不输出筛选建议。
- 不用于招聘、录用、淘汰、分层、排名。

### 用例 10：手机端体验

检查：

- 字体是否正常。
- 输入框是否好用。
- 按钮是否遮挡。
- 输出内容是否看得懂。
- 是否有明显错位。

期望：

- 手机端可完成最小流程。
- 无阻塞性错位或遮挡。
- 输出文案能被普通用户理解。
