# AIPIWEN Report Upload P0 API 草稿审阅意见

版本：V0.1  
审阅对象：`api/report-upload-p0.js`  
审阅结论：建议暂时保留，但必须等 V1.0 规则冻结包完成后再决定是否继续改造和提交。  
处理建议分类：B. 可保留，但必须等 V1.0 规则冻结包完成后再改。

## 1. 文件定位

`api/report-upload-p0.js` 是一个未跟踪的上传报告 P0 API 草稿，文件头部明确标注为“上传报告 P0 决策 API（rules/mock 版）”。

它不是 Report OS 文档，不是 V1.0 规则冻结包，也不是完整报告生成系统。它更像是把 P0 决策规则提前写成了一个最小后端接口草稿。

由于当前阶段仍在做 Report OS P0 规则冻结准备，该 API 文件出现得偏早。它不应在 V1.0 规则冻结完成前进入 commit，也不应混入 docs-only 提交。

## 2. 功能摘要

该文件提供两个入口：

- `GET /api/report-upload-p0`：健康检查，返回版本和服务名。
- `POST /api/report-upload-p0`：读取 JSON payload，输出资料完整度、风险等级、置信度、下一步动作、追问问题、快速读懂或降级 sections。

主要内部逻辑：

- `readJson`：读取 JSON 请求体，限制最大 512KB。
- `detectMetrics`：从 `extracted.fingers`、`extracted.atd`、`extracted.age`、`rawText` 判断 TRC / ATD / age / raw_text。
- `judgeCompleteness`：判断 `complete / partial / unreadable / unknown`。
- `judgeRisk`：基于硬编码词表判断 R0 / R1 / R2 / R3。
- `judgeConfidence`：判断 `high / medium / low / insufficient`。
- `decideNextStep`：决定 `generate_quick_read / ask_followup / safety_limited / refer_human`。
- `buildFollowups`：生成最多 1-3 个追问。
- `buildQuickReadSections`：生成快速读懂 sections。
- `buildLimitedSections`：生成降级输出 sections。

## 4. 是否越过 P0

总体没有明显越过 P0。

符合 P0 的部分：

- 上传报告解析的后置决策。
- 用户身份识别字段。
- 用户目的识别字段。
- 报告对象识别字段。
- R0-R3 风险判断。
- 置信度判断。
- 快速读懂报告。
- 轻量建议。
- 追问。
- 降级输出。
- 转人工建议。

未发现直接开放以下能力：

- 个人完整长报告。
- 亲子正式合看。
- 亲密关系合看。
- 合伙人合看。
- 团队画像。
- 班级画像。
- 企业画像。
- 长期陪伴。
- 自动知识卡沉淀。
- Obsidian 直接导入。

需要注意：草稿中出现“如果要做深度解读，建议补齐完整报告”等提示，但它没有实际生成完整长报告，只是建议人工或后续补充，因此不构成越界。

## 5. 安全风险检查

### 5.1 硬编码密钥 / 隐私信息

未发现：

- API key。
- token。
- 管理员密码。
- 私人手机号、身份证、地址。
- 真实用户资料。
- `process.env` 读取。
- 第三方模型调用配置。

### 5.2 代码安全风险

存在以下工程风险，但不属于密钥泄漏：

1. CORS 当前是 `Access-Control-Allow-Origin: *`。如果进入真实后端，需要按产品入口限制来源或确认匿名接口策略。
2. 没有鉴权或速率限制。作为 mock 可以接受，作为正式 API 不够。
3. `debug.ruleHits` 会返回命中的风险词。测试阶段有价值，但生产前应移除或仅内部可见，避免回显敏感词。
4. 风险判断是硬编码关键词匹配，容易漏判、误判，不能作为最终安全体系。
5. 未成年人授权只生成 `pending`，但没有真正阻断未授权深度输出的完整策略。
6. 请求体最大 512KB 有限制，方向正确，但还缺少字段白名单和输出日志脱敏策略。

### 5.3 内容安全风险

未发现医学、心理、脑科学强判断。文件把以下方向列入 R2/R3 或边界说明：

- 医学诊断。
- 心理诊断。
- 自伤暴力。
- 升学保证。
- 职业命定。
- 关系重大决定。
- 招聘淘汰。
- 学校个体筛查。
- 孩子标签化。

整体符合 Report OS 安全边界。

## 6. 是否引用错误路径

该文件没有引用：

- `docs/aipiwen_report_system`
- `08_schema_结构化输出`
- `08_schema_结构化规则`
- Obsidian
- 任何本地文档路径

因此不存在“引用错误路径”的问题。

但由于它没有直接引用 Report OS 文档或 Schema，当前只是规则手写版 mock。进入代码阶段前，应与实际存在的 `08_schema_结构化规则/` 下的 Schema 对齐，而不是引用不存在的 `08_schema_结构化输出/`。

## 7. 与 Report OS 文档体系的关系

该 API 草稿与 V0.9 最小 P0 边界基本一致：

- 先判断完整度。
- 再判断风险等级。
- 再判断置信度。
- 再决定快速读懂、追问、降级或转人工。
- R3 不进入普通报告。
- R2 降级。
- R0/R1 且 high/medium 才生成快速读懂。

与现有文档的关系：

- 与 `AIPIWEN_ReportOS_V0.9_总体验收与产品改造准备清单.md` 一致。
- 与 `AIPIWEN_上传报告输出规则_V0.1.md` 一致。
- 与 `AIPIWEN_上传报告输入字段Schema_V0.1.md`、`AIPIWEN_上传报告输出总流程Schema_V0.1.md`、`AIPIWEN_风险等级与安全拦截Schema_V0.1.md`、`AIPIWEN_置信度与降级输出Schema_V0.1.md` 方向一致。
- 与 `AIPIWEN_Prompt调用总流程_V0.1.md` 的“先解析、再追问/风险/置信度、再选择输出”一致。
- 与 `AIPIWEN_报告生成质量验收标准_V0.1.md` 的安全要求一致。

主要不足：它没有从 Schema 生成或严格实现 Schema，只是手写了一个初版规则实现。

## 8. 是否适合保留

建议保留，但暂不提交。

理由：

- 它没有明显越过 P0。
- 它没有发现密钥或隐私泄漏。
- 它可作为后续代码阶段的最小 mock 参考。
- 它把 V0.9 的 P0 判断链路转成了一个可执行雏形。

但不建议现在纳入 commit：

- 当前还没有完成 V1.0 规则冻结包。
- 当前 API 没有鉴权、速率限制、生产级日志脱敏和测试覆盖。
- 当前规则词表只是硬编码草稿。
- 当前 debug 输出不适合生产。
- 当前文件是代码，不应混入 Report OS docs 审阅或规则冻结提交。

## 9. 是否建议移动 / 归档 / 删除

不建议删除。

建议优先级：

1. 当前先保持未跟踪状态，不提交。
2. 如需要保持工作区干净，可临时移出仓库或另存 patch，但本轮不执行。
3. V1.0 规则冻结包完成后，再决定是否继续从该草稿演进。
4. 若进入代码阶段，应在单独代码 commit 中处理，不与 docs commit 混合。

因此建议：等 V1.0 后再处理，不建议现在归档或删除。

## 10. 是否建议纳入后续代码阶段

建议作为后续代码阶段参考，但不能直接作为最终实现。

可复用方向：

- `R0/R1/R2/R3` 决策结构。
- `high/medium/low/insufficient` 置信度结构。
- `generate_quick_read / ask_followup / safety_limited / refer_human` 输出路径。
- 请求体大小限制。
- 快速读懂和降级 sections 的低风险结构。

- 鉴权或匿名访问边界。
- 速率限制。
- 生产日志脱敏。
- 移除或限制 `debug.ruleHits`。
- 与 `08_schema_结构化规则/` 文档逐项对齐。
- 正向和反向测试样本覆盖。
- 未成年人授权规则。
- R3 专业支持和人工转接话术。

## 11. 进入代码阶段前必须补齐的条件

进入正式代码改造前，至少需要满足：

1. V1.0 P0 运行规则冻结包已完成。
2. 明确该 API 是否作为正式路径、mock 路径还是实验路径。
3. 当前未跟踪 docs 文件已完成取舍，避免混合提交。
4. API 请求字段与 `08_schema_结构化规则/` 下的 Schema 对齐。
5. R0-R3 风险矩阵和 25 个高风险负向样本可用于测试。
6. 20 个正向样本可验证快速读懂输出。
7. 移除或保护 debug 输出。
8. 明确未成年人、他人报告、学校/企业场景的授权和阻断规则。
9. 明确是否允许匿名调用，以及速率限制策略。
10. 确认不会修改 homepage、普通页面、`vercel.json` 或非 P0 API。
