## 1. V1.0 定位

V1.0 不是继续扩展资料库，不吸收新课程、新案例、新行业资料，也不做 Obsidian 全量导入。

V1.0 是上传报告 P0 的运行规则冻结文件。它的目标是把 Report OS V0.1-V0.9 已形成的资料、Schema、Prompt、测试样本、安全边界和审阅结论，冻结成后续代码阶段可执行的统一规则。

后续代码阶段必须以本文件为最高优先级依据。当本文件与 P0 实施方案、API 草稿或早期工程设想不一致时，以本文件为准。

`AIPIWEN_ReportUpload_P0_实施方案.md` 只能作为代码实施参考，不能高于本文件。`lib/report-upload-p0-dryrun.js` 只能作为 mock/rules dry-run 模块参考，不能高于本文件；当前不是生产 API route，后续进入真实 P0 API 时再决定是否合并到现有 API 或调整部署方案。

本文件不定义页面设计、不写代码、不做商业包装、不扩大产品能力。

## 3. P0 允许范围

上传报告 P0 只允许做以下能力：

- 上传报告解析。
- 文件 / 文本可读性检查。
- 报告类型识别。
- 报告对象识别。
- 用户身份识别。
- 用户目的识别。
- 敏感场景识别。
- R0-R3 风险等级判断。
- `high / medium / low / insufficient` 置信度判断。
- 输出路径选择。
- 快速读懂报告。
- 轻量建议。
- 必要追问。
- 安全降级。
- 转人工建议。
- 人工复核触发。

P0 的核心产出不是“完整报告”，而是判断用户上传内容后，系统应该输出什么、不输出什么、追问什么、何时停止。

## 4. P0 禁止范围

上传报告 P0 不允许开放以下能力：

- 个人完整长报告。
- 亲子正式合看。
- 亲密关系正式合看。
- 合伙人合看。
- 团队画像。
- 班级画像。
- 企业画像。
- 招聘筛选。
- 学生分层。
- 定岗定责。
- 长期陪伴。
- 自动知识卡沉淀。
- Obsidian 全量接入。
- 医学判断。
- 心理诊断。
- 脑科学强结论。
- 疾病倾向判断。
- 职业保证。
- 升学保证。
- 关系去留判断。
- 父母责任归因。
- 孩子标签化。
- 命定化 / 玄学化表达。

任何用户目标如果落入上述范围，系统不能直接生成普通报告，必须进入追问、降级、转人工或专业支持提示。

## 5. 上传报告主流程

上传报告 P0 必须遵守“先判断，再生成”。禁止从上传内容直接进入完整报告生成。

主流程：

1. 接收上传内容。
2. 判断文件、图片、文本或结构化数据是否可读。
3. 判断是否属于 AIPIWEN 可处理的报告或可解释材料。
4. 识别报告对象：本人、孩子、成人、双人、多方、班级、团队或未知。
5. 识别用户身份。
6. 识别用户目的。
7. 识别敏感场景。
8. 进行 R0-R3 风险等级判断。
9. 进行 `high / medium / low / insufficient` 置信度判断。
10. 决定输出路径。
11. 生成追问、快速读懂、降级输出或转人工建议。
12. 记录人工复核触发原因。

流程硬规则：

- 未识别用户目的，不生成报告。
- 未完成风险判断，不生成报告。
- 未完成置信度判断，不生成报告。
- R3 不进入普通报告模板。
- R2 不输出完整结论。
- 低置信度不输出完整报告。
- 涉及未成年人、学校、企业、关系重大判断时，默认提高风险等级。

## 6. 用户身份识别规则

用户身份影响输出视角、风险等级、授权要求和前台表达边界。

| 用户身份 | 识别说明 | P0 输出边界 |
| --- | --- | --- |
| 本人 | 成人本人看自己的报告 | 可快速读懂和轻量建议，不做医学、职业命定或关系结论 |
| 父母 / 监护人 | 为孩子查看报告 | 默认至少 R1；涉及问题行为、学习困难或亲子冲突时可能 R2 |
| 老师 | 为学生或班级查看报告 | 只能做支持策略，不做个体标签、排名、筛查 |
| 咨询顾问 | 为客户解读 | 可辅助整理资料和风险提示，复杂个案建议人工专家复核 |
| 伴侣 | 为亲密关系查看 | P0 不做正式合看，不判断适合、不劝分合 |
| 合伙人 | 为合作关系查看 | P0 不做正式合伙人合看，不给投资、股权、合作去留结论 |
| 企业管理者 | 为员工或团队查看 | P0 不做筛人、淘汰、定岗、排序 |
| 学校 / 机构人员 | 为学生、班级或机构查看 | 必须优先检查授权、脱敏和用途限定 |
| 未知身份 | 无法识别当前使用者 | 必须追问身份，不直接生成报告 |

默认升风险规则：

- 涉及未成年人：至少 R1。
- 涉及学校、班级、企业、团队：至少 R1。
- 涉及他人资料且授权不清：至少 R2。
- 涉及个体筛查、淘汰、排名、风险学生：R3。
- 涉及亲密关系重大决定、法律财务、暴力或安全风险：R3 或转专业支持。

## 7. 用户目的识别规则

P0 必须先识别用户目的。目的不清楚时，不得直接生成报告，必须追问。

| 用户目的 | P0 判断 | 系统动作 |
| --- | --- | --- |
| 想快速读懂报告 | P0 允许 | 若 R0/R1 且置信度 high/medium，可生成快速读懂 |
| 想理解孩子行为 | P0 允许轻量版 | 先问年龄、场景、持续时间；避免标签化 |
| 想改善亲子沟通 | P0 允许降级或追问 | 不做正式亲子合看，只给低风险沟通问题清单 |
| 想看学习 / 职业方向 | P0 允许轻量建议 | 只做探索和验证建议，不给保证或定论 |
| 想判断关系 | P0 不开放正式判断 | 降级、追问或转人工，不判断合不合 |
| 想判断合伙人 | P0 不开放正式判断 | 不给合作去留、股权、投资、法律财务结论 |
| 想用于团队管理 | P0 不开放团队画像 | 只能提示用途边界或转人工 |
| 想用于学校分层 | P0 禁止 | 阻断个体分层、排名、风险标签 |
| 想用于招聘筛选 | P0 禁止 | 阻断筛选、淘汰、录用建议 |
| 想诊断心理 / 医学问题 | P0 禁止 | R3，提示专业评估或专业支持 |
| 目的不清楚 | 信息不足 | 先追问，不生成报告 |

追问规则：

- 每轮最多 1-3 个关键问题。
- 优先问“你想用这份报告解决什么”。
- 涉及孩子时优先问年龄和具体场景。
- 涉及他人或多人时优先问关系、授权和使用目的。
- 用户不愿补充时，只能输出 low 或 insufficient 路径下的低风险提示。

## 8. R0-R3 风险等级规则

风险等级用于决定系统动作，不是用户标签，也不是报告结论。

| 风险等级 | 定义 | 允许输出 | 系统动作 |
| --- | --- | --- | --- |
| R0 | 低风险普通理解 | 快速读懂、轻量建议、边界说明 | 可输出 |
| R1 | 轻微敏感 | 安全话术后的倾向性解释、低标签建议 | 安全改写后输出 |
| R2 | 中高风险 | 观察方向、补充问题、边界说明、人工复核建议 | 降级输出，不给确定判断 |
| R3 | 高风险 | 不输出报告结论，只做边界提示、转人工或专业支持 | 阻断普通报告 |

必须覆盖的风险来源：

- 未成年人。
- 医学 / 心理。
- 脑科学强结论。
- 催眠 / 疗愈 / 症状转化。
- 关系判断。
- 职业 / 升学保证。
- 企业 / 学校筛选。
- 命定化 / 玄学化。
- 父母责任归因。
- 孩子标签化。
- 数据隐私和授权不清。

风险升级规则：

- 同时命中多个风险时，取最高风险等级。
- 命中医学诊断、心理诊断、自伤暴力、疾病判断：R3。
- 命中升学保证、职业命定、关系去留、招聘淘汰、风险学生：R3。
- 命中孩子标签、父母归因、关系绝对化：至少 R2。
- 未成年人授权不清：至少 R2。
- 学校或企业个体数据用于筛查、排名、淘汰：R3。
- 脑科学、医养、康养、症状转化等强结论：R3 或内部参考，不进入普通输出。

## 9. 置信度规则

置信度不是模型自信，而是“输入资料是否足够支持当前输出”。

| 置信度 | 定义 | 输出策略 |
| --- | --- | --- |
| high | 报告信息完整、用户目的明确、风险低、字段充足 | 可生成快速读懂和轻量建议，仍需边界说明 |
| medium | 信息基本可用，但缺少部分字段或场景 | 可生成快速读懂，但必须保守表达 |
| low | 信息不足、目的不清或资料片段化 | 只输出方向性提示、观察点或追问 |
| insufficient | 无法生成、授权缺失、资料不可读或命中高风险 | 不生成报告，必须追问、降级或转人工 |

判断依据：

- 报告是否可读。
- 核心指标是否识别。
- 用户身份是否明确。
- 用户目的是否明确。
- 报告对象和年龄是否明确。
- 是否涉及多人、未成年人、学校、企业或关系场景。
- 是否存在敏感风险。
- 是否存在授权缺失或隐私问题。

硬规则：

- R3 一律视为 insufficient 或直接转人工 / 专业支持。
- R2 不因资料完整而输出确定结论。
- 用户目的不明确时，置信度不得为 high。
- 授权不清时，置信度不得为 high。
- 资料不可读时，置信度为 insufficient。

## 10. 输出路径决策表

| 风险等级 | 置信度 | 系统动作 | 禁止动作 |
| --- | --- | --- | --- |
| R0 | high | 生成快速读懂报告 | 不生成完整长报告 |
| R0 | medium | 生成快速读懂，并加限制说明 | 不写成确定结论 |
| R0 | low | 输出轻量提示 + 追问 | 不生成报告 |
| R0 | insufficient | 追问，不生成报告 | 不伪造资料 |
| R1 | high | 安全改写后输出快速读懂 | 不输出原始高风险词 |
| R1 | medium | 安全改写 + 限制说明 | 不扩大解释 |
| R1 | low | 优先追问 | 不生成完整报告 |
| R1 | insufficient | 追问或转人工 | 不做实质结论 |
| R2 | 任意置信度 | 降级输出，不给结论 | 不输出完整报告、关系结论、职业/升学判断 |
| R3 | 任意置信度 | 阻断或转人工 / 专业支持 | 不生成普通报告 |

输出路径枚举：

- `generate_quick_read`：仅 R0/R1 + high/medium。
- `ask_followup`：目的、身份、对象、年龄、授权或资料缺失。
- `safety_limited_output`：R2 或 low。
- `refer_human`：复杂关系、深度解读、重大职业/财务/法律、团队/学校高风险。
- `suggest_professional_help`：医学、心理、自伤暴力、严重危机。

## 11. P0 快速读懂报告结构

P0 前台可输出结构固定为短报告：

1. 这份报告大概在讲什么。
2. 你现在最关心的问题。
3. 可以参考的 3-5 个理解点。
4. 需要结合后天环境观察的地方。
5. 不建议直接下结论的地方。
6. 可以尝试的沟通 / 观察建议。
7. 是否建议人工解读。

必须包含的边界：

- 这是快速读懂，不是完整长报告。
- 报告只作理解和沟通参考。
- 需要结合真实环境、年龄阶段和持续观察。
- 低置信度内容必须标注资料不足。

禁止输出：

- “这个孩子就是……”
- “这个人一定……”
- “适合 / 不适合某职业或关系。”
- 医学、心理、疾病、脑科学强判断。
- 升学、职业、关系保证。
- 对父母、孩子、伴侣、员工、学生的责任归因或标签化。

## 12. 行为倒推与后天环境校正规则

V0.8 外部机构培训资料可以进入 P0，但必须经过安全改写。

允许表达结构：

```text
表现 -> 可能机制 -> 后天环境影响 -> 可观察验证 -> 轻量建议
```

执行要求：

- 先问场景，不先下结论。
- 先拆行为，不先贴标签。
- 先看持续时间、频率和影响范围，再决定输出深度。
- 有报告时用报告做辅助理解，没有报告时只做观察方向。
- 用户说“不像我 / 不像孩子”时，把不一致当作后天环境、当前角色或资料质量的校正线索。

禁止表达结构：

```text
表现 -> 性格定型
表现 -> 天赋定论
表现 -> 父母责任归因
表现 -> 未来命运判断
表现 -> 心理/医学结论
```

前台公式：

```text
先天倾向 + 后天环境 + 当前场景 = 当下表现
```

说明：当下表现不等于完整人格。报告指标只能作为参考底色，不能替代现实观察。

## 13. 未成年人安全规则

涉及孩子、学生、未成年人时，默认至少 R1。

升级规则：

- 涉及轻度学习方式、兴趣、沟通：R1。
- 涉及问题行为、情绪、学习困难、亲子冲突：通常 R2 或至少需要安全改写。
- 涉及诊断、创伤、疾病、自伤、他伤、严重心理风险：R3 或转人工 / 专业支持。
- 年龄未知、监护人授权不清、学校用途不清：至少 R2。
- 学校或机构要求个体标签、分层、风险识别、排名：R3。

禁止表达：

- “这个孩子就是……”
- “孩子天生不适合……”
- “父母导致了……”
- “必须改变孩子……”
- “未来一定……”
- “适合 / 不适合某条升学路径。”
- “问题孩子 / 风险学生 / 不努力 / 懒 / 笨。”

允许表达：

- “这个行为需要结合年龄、环境和互动方式理解。”
- “当前更适合先观察具体场景和持续时间。”
- “可以先尝试低压力、可验证的小动作。”
- “如果长期影响睡眠、学习、情绪或生活，建议寻求专业评估。”

## 14. 关系 / 团队 / 学校 / 企业场景规则

以下场景 P0 不开放正式报告，只能识别、降级、追问或转人工：

- 亲子正式合看。
- 亲密关系。
- 合伙人。
- 团队。
- 班级。
- 企业。
- 招聘。
- 分班。
- 定岗。
- 淘汰。

P0 可输出：

- “该场景较复杂，建议人工解读。”
- “可以先说明你想解决的具体问题。”
- “可以先整理双方 / 多方的关注点和沟通问题。”
- “团队或班级资料只能用于支持策略，不用于个体评价。”

P0 不输出：

- 谁对谁错。
- 是否适合在一起。
- 是否适合合作。
- 是否适合录用。
- 谁应该被淘汰。
- 哪个孩子应该被分层。
- 哪个员工是风险人员。
- 哪位老师或家长有问题。

多人、学校、企业资料进入任何输出前，必须先检查授权、脱敏、用途限定和最小必要原则。

## 15. Prompt 对接规则

后续 Prompt 不得写成一个大 Prompt，必须拆成可路由、可测试、可降级的流程。

必备 Prompt：

1. 报告解析 Prompt。
2. 用户身份与目的识别 Prompt。
3. 风险判断 Prompt。
4. 置信度判断 Prompt。
5. 输出路径选择 Prompt。
6. 快速读懂报告 Prompt。
7. 追问生成 Prompt。
8. 降级输出 Prompt。
9. 转人工建议 Prompt。
10. 安全改写 Prompt。

调用顺序：

1. 先解析。
2. 再识别身份、对象和目的。
3. 再判断是否需要追问。
4. 再判断风险。
5. 再判断置信度。
6. 再选择输出路径。
7. 再生成快速读懂、追问、降级或转人工。
8. 再做安全改写。

硬规则：

- 风险判断必须发生在报告生成前。
- 置信度判断必须发生在报告生成前。
- R3 不能调用普通报告 Prompt。
- low / insufficient 不能调用完整报告 Prompt。
- Prompt 输出必须可被测试样本验证。

## 16. Schema 对接规则

后续工程至少需要以下 Schema。实际文档目录必须使用：

```text
docs/aipiwen_report_system/08_schema_结构化规则/
```

| Schema | 用途 | 关键字段方向 |
| --- | --- | --- |
| `ReportUploadInputSchema` | 接收上传输入 | `upload_id`, `user_id`, `source_type`, 文件/文本摘要, `upload_time` |
| `ReportParseResultSchema` | 记录解析结果 | `report_completeness`, `detected_metrics`, `missing_metrics`, 可读性、资料类型 |
| `UserIdentitySchema` | 识别使用者身份 | 本人、父母、老师、顾问、伴侣、合伙人、企业/学校人员、未知 |
| `UserIntentSchema` | 识别用户目的 | 快速读懂、孩子行为、学习/职业、关系、团队、学校、医学心理、未知 |
| `SensitiveScenarioSchema` | 识别敏感场景 | 未成年人、医学/心理、自伤暴力、关系重大决策、学校/企业筛选、隐私授权 |
| `RiskAssessmentSchema` | 输出 R0-R3 | `risk_level`, `risk_flags`, `risk_reason`, `system_action` |
| `ConfidenceAssessmentSchema` | 输出置信度 | `confidence_level`, `confidence_reason`, `missing_fields`, `allowed_depth` |
| `OutputDecisionSchema` | 选择输出路径 | `next_step`, `selected_report_type`, `should_ask_followup`, `should_refer_human` |
| `QuickReadingReportSchema` | 快速读懂报告 | 7 个 P0 章节、边界说明、轻量建议 |
| `ClarificationQuestionSchema` | 追问 | 1-3 个问题、追问原因、用户不答时的降级路径 |
| `FallbackOutputSchema` | 降级输出 | 可做范围、不可做范围、观察方向、补充资料、边界说明 |
| `HumanReviewTriggerSchema` | 人工复核 | 触发类型、风险等级、用户问题、资料摘要、建议转人工原因 |

P0 不要求本轮写完整 JSON Schema，但代码阶段必须把字段与现有 `08_schema_结构化规则/` 对齐。

## 17. 测试样本验收规则

P0 上线前必须跑以下测试：

- 20 个正向样本。
- 25 个高风险负向样本。
- R0-R3 风险矩阵。
- 安全改写词表。
- 未成年人样本。
- 关系样本。
- 企业 / 学校禁用样本。
- 人工复核流程。

每个样本必须包含：

- 期望输出类型。
- 禁止输出内容。
- 是否应追问。
- 是否应降级。
- 是否应转人工。
- 风险等级预期。
- 置信度预期。

上线前最低标准：

- 正向样本通过率 >= 95%。
- 高风险反向样本拦截通过率 100%。
- R3 不得进入普通报告生成。
- 医学 / 心理、未成年人、转人工相关评分项不得为 0。
- 企业 / 学校样本不得输出个体淘汰、排名、筛查或风险标签。
- 低置信度资料不得生成完整结论。

进入代码阶段前必须补齐：

- 速率限制。
- 文件大小限制。
- 上传类型限制。

- 日志脱敏。
- 人工复核触发机制。

## 19. Obsidian 与专家课程接入原则

Obsidian 是长期知识矿山，不在 P0 前全量接入。

专家课程、外部课程、书籍、案例后续可以进入 Obsidian，但必须分级：

| 等级 | 含义 | 是否可进入前台 |
| --- | --- | --- |
| A 类 | 可进入 Obsidian 原始知识库 | 不自动进入前台 |
| B 类 | 可转成 Report OS 内部参考卡 | 仅内部使用 |
| C 类 | 需要安全改写后才能用于前台报告 | 改写并测试后有限使用 |
| D 类 | 禁止进入前台报告 | 不进入前台 |

特别规则：

- 心理、催眠、疗愈、原生家庭、症状转化、潜意识、儿童人格等内容，不得原文进入前台报告生成层。
- 任何知识卡沉淀前必须脱敏、分级、审核。
- P0 不做自动知识卡沉淀。
- P0 不允许把 Obsidian 内容直接接入生成链路。
- 行业大会、外部机构、老师现场口语均不得原文进入前台。

## 20. V1.0 后续执行顺序

推荐执行顺序：

1. 完成 V1.0 规则冻结包。
2. 审阅并决定是否提交 P0 实施方案和两个审阅意见。
3. 冻结 Schema / Prompt / Test Case 对齐清单。
4. 再进入 `lib/report-upload-p0-dryrun.js` 代码阶段。
5. 本地测试。
6. 样本验收。
7. 人工复核。
8. 灰度上线。

执行限制：

- 代码阶段前不得继续扩展资料库。
- 代码阶段前不得把 API 草稿提交为正式实现。
- 代码阶段不得混入首页、普通页面、商业包装、微信小店、大会 PPT 或 Obsidian 导入。
- 灰度上线前必须通过测试样本和人工复核。

## 21. 总结结论

Report OS V1.0 P0 的核心不是“生成更完整报告”，而是让系统稳定、克制、安全地判断上传报告后应该输出什么、不输出什么、何时追问、何时降级、何时停止。

P0 可以做快速读懂和轻量建议，但必须把风险、置信度、用户目的、授权和输出边界放在生成之前。

后续任何代码改造，如果绕过本文件定义的判断链路，直接从上传内容进入完整报告生成，都应视为不符合 Report OS V1.0 P0。
