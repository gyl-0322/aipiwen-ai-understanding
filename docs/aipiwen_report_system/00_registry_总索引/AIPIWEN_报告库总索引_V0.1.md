# AIPIWEN 报告库总索引 V0.1

## 1. Report OS 定位

AIPIWEN Report OS 是面向产品调用的报告库，不是普通资料库。它负责把老师解读、外部培训、关系模板和 Obsidian 知识湖中的内容，筛选为可解释、可组合、可安全输出的报告模块。

Report OS V0.1 的核心目标：

- 支撑上传报告、行为理解、皮纹速测、关系合看、团队协作理解等入口。
- 把原始资料改写成指标卡、场景卡、关系卡、案例卡、话术卡、安全卡和版式卡。
- 让同一份资料按用户目的调用不同模板，而不是上传后直接生成长文。
- 避免诊断、贴标签、玄学化、绝对化和伤害性表达。

## 2. Report OS 与 Obsidian 的关系

Obsidian 是底层知识湖，保存老师课程、心理学材料、皮纹资料、历史分析和规则设定。Report OS 是产品级报告库，只吸收经过筛选、结构化和安全改写的内容。

Obsidian 内容进入 Report OS 前必须判断：

1. 能否前台输出。
2. 是否需要安全改写。
3. 适合哪个产品入口调用。
4. 是否存在医学、心理诊断、玄学、绝对化或伤害性标签风险。
5. 是否只是原始资料，不适合产品直接调用。

Obsidian 后续整理按五类分流：

| 分类 | 处理方式 |
| --- | --- |
| 可进入报告库的内容 | 改写为知识卡、报告模块或版式规则 |
| 只能做内部专家参考的内容 | 标记为 C 级，不进入自动前台输出 |
| 可进入案例库的内容 | 转写为标准案例卡，保留来源和边界 |
| 可进入心理学支撑库的内容 | 只作为解释支撑，不做诊断依据 |
| 暂不进入产品的原始资料 | 保留索引，不进入 Prompt 或前台输出 |

## 7. 可前台输出

- 安全改写后的指标解释。
- 低断言、低标签的行为理解。
- 面向学习、沟通、协作、陪伴的建议。
- 关系差异、沟通节奏、情绪需要、行动计划。
- 明确标注置信度和边界的皮纹速测轻量画像。

## 8. 只供内部参考

- 老师现场录音原话。
- 外部机构培训中的口语化判断。
- 未经校验的“君臣佐使”组合推断。
- 成人职业和亲子个案中的具体隐私细节。
- 需要人工专家判断的复杂关系冲突。

## 9. 禁止输出

- 医学或心理诊断。
- “注定、一定会、绝对、永远、必然”等绝对化表达。
- “抑郁体质、心理疾病、有问题、障碍”等诊断或类诊断表达。
- “懒、白眼狼、不懂感情、脚底板人”等伤害性标签。
- “前世、天命、缘分密码、命中注定”等玄学化表达。
- 直接照搬老师口语、外部机构培训原话或模板原文。

## 10. 知识卡标准格式

每张知识卡必须包含：

```yaml
card_id: ""
card_type: "metric | scenario | relationship | case | language | safety | layout | prompt_rule"
title: ""
source: ""
applicable_entries:
  - upload_report
  - behavior_understanding
  - fingerprint_quick_test
  - relationship_report
  - team_report
usable_level: "A | B | C | D"
core_logic: ""
safe_output: ""
forbidden_output: ""
related_metrics: []
related_cases: []
confidence_notes: ""
```

可用等级：

| 等级 | 含义 |
| --- | --- |
| A | 前台可直接输出 |
| B | 安全改写后可输出 |
| C | 只供人工专家参考 |
| D | 禁止输出 |

## 11. 产品调用规则总览

### 上传报告调用

上传文件 -> 识别报告类型 -> 提取指标 -> 识别用户目的 -> 选择报告模板 -> 调用指标解释卡 + 场景规则 + 版式模板 -> 生成报告

### 行为理解调用

用户描述行为 -> 识别行为场景 -> 调用案例库 -> 调用可能相关指标 -> 输出行为解释 + 回应建议 -> 必要时提示专业帮助

### 皮纹速测调用

用户选择纹型 -> 生成低置信度基础画像 -> 调用简版指标卡 -> 输出轻量理解 + 引导完整采集 -> 不得输出确定性结论

### 关系合看调用

双方或多方资料 -> 差异对比 -> 冲突点 -> 互补点 -> 场景建议 -> 行动计划

### 13.1 Report OS 与 Industry Intelligence 的关系

- Report OS 是可被产品调用的报告生成知识库，负责指标解释、案例、模板、规则和安全输出。
- Industry Intelligence 是 Report OS 的上游战略层，负责判断行业方向、AI 能力边界、合规风险和商业表达。
- 行业大会原始表达不能直接进入前台，也不能直接写入自动报告结论。
- 进入产品前必须经过三层转换：行业趋势 -> AIPIWEN 产品策略 -> 安全可输出规则。
- 涉及脑科学、医养、疾病、康养、全生命周期养护的内容，只能作为远期研究方向或内部观察方向。

### 15.1 Prompt Pack 与 Schema 的关系

- Schema 负责“系统知道什么、该走哪条路、风险多高、置信度如何”。
- Prompt Pack 负责“在这条路上如何生成安全、温和、可行动的文本”。
- Schema 是路由和控制层，Prompt Pack 是生成和表达层。
- Prompt Pack 不能绕过 Schema 独立生成报告。
- 任何 Prompt 输出后仍需经过安全改写和转人工判断。

### 17.2 V0.8 安全边界

- 外部培训原话不得直接进入前台。
- 医学、心理、疾病、用药、诊断、命理、生命使命、职业婚恋决定论必须改写或禁用。
- 报告只能作为倾向和辅助理解参考。
- AI 只能做资料整理、低风险解释和追问，不替代人工专家。
