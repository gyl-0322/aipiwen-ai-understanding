审计方式：真实浏览器导航、DOM 状态核对、当前部署代码只读检查  
数据边界：未上传文件、未生成新归属码、未生成或保存真实客户解读、未退出账号、未修改数据库

## 1. 结论

状态：**NEEDS FIX**

“客户扫码上传”链路符合当前产品目标；“代客户上传报告”链路不符合产品目标。两者目前共用同一套归属 token 和公开 `report-upload.html` 页面，导致指导师代传时也进入客户可见的自动报告页面，并被归类为 `advisor_qr / 客户扫码`。

真实客户列表中的“开始解读”可以正确携带 `clientId + reportId` 进入 AI 解读助手，但进入后仍需指导师再次点击“生成 AI 解读方案”，尚未实现首次进入自动生成。

## 2. 正确产品链路（本次确认）

### 客户扫码上传

`客户扫码上传` → 生成一次性归属码/二维码 → 客户打开公开 `report-upload.html?token=…` → OCR → 客户确认 → 生成客户可见报告 → 写入指导师“我的客户” → `source=advisor_qr`

结论：当前方向正确，应保留。

### 指导师代客户上传

`代客户上传报告` → 指导师工作台内的受保护上传界面 → OCR → 指导师确认客户和十指数据 → 调用现有 `/api/v3a-report-import?action=confirm` → 写入客户与报告 → `source=advisor_import` → 返回“我的客户” → 点击“开始解读” → AI 解读助手首次自动生成方案

结论：当前前端未实现这条链路，但后端 `v3a-report-import` 的 extract/confirm 能力已经存在，不应新建第二套 OCR 或 Report Engine。

## 4. 根因证据

### P1-1：两种上传共用同一条公开链路

`static/v3a-attribution.js` 中：

- `uploadForCustomer()` 先调用 `createToken()`，再跳转 `payload.uploadPath`；
- `showQr()` 也调用同一个 `createToken()`；
- 两个按钮分别绑定上述函数，但归属能力和上传页面完全相同。

因此“代客户上传”没有独立的 `advisor_import` 入口。

### P1-2：现有安全 BFF 没有前端入口

`api/v3a-report-import.js` 已提供：

- `action=extract`：受保护的图片识别；
- `action=confirm`：确认客户、调用 `v3a_create_advisor_report_import`、生成报告并完成入库；
- 从 Session 推导指导师，不接受浏览器指定 `advisor_id`。

当前没有页面或组件调用这两个 action。

### P1-3：首次进入 AI 解读助手不会自动生成

`static/ai-interpreter.js` 在报告无既有解读方案时只显示“点击生成”，并启用按钮；不会自动调用 `generateInterpretation()`。

### P1-4：两个无上下文入口

- 侧栏 `AI解读助手` 固定链接到 `ai-interpreter-session.html`；
- 工作台“最近解读记录”四个学习示例也固定链接到同一无参数地址；
- 解读页要求合法 `clientId + reportId`，否则无法加载真实报告。

## 5. 最小修复边界建议

1. 保留客户扫码和首页服务码链路，不修改公开 `report-upload.html` 的客户体验。
2. 将“代客户上传报告”改为工作台受保护导入流程，复用现有 `v3a-report-import` BFF。
3. 导入成功后回到“我的客户”，新记录显示 `代客户上传`，而不是 `客户扫码`。
4. “开始解读”保持携带真实 `clientId + reportId`。
5. 解读页首次加载且没有既有方案时自动调用生成；已有方案只读取，不重复生成。
6. 侧栏“AI解读助手”改为客户选择入口，不能打开无上下文空页。
7. 工作台学习示例记录取消虚假跳转；若展示真实最近记录，则必须来自真实 API 并携带标识。
8. 搜索、筛选、排序在接入真实逻辑前不要展示为可用控件。
